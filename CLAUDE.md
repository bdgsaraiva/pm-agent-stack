# pm-agent-stack — rules for any Claude session in this repo

This is Bernardo's **personal** build of a PM agent stack (Steps 1–3 of the blueprint in `docs/architecture.md`). It runs on public data only.

## Hard rules
- **No fund data here.** Never write the fund's positions, sizes, P&L, order history, broker research or proprietary notes into this repo, a prompt, a note or a log — not even as a summary. `portfolio/` and `journal/` hold dummy or public-idea files only. The corporate build lives elsewhere.
- **Numbers come from code.** Agents quote figures only from `briefs/<date>/facts.md` (or a DuckDB query over `data/`, the journal, or a critic card), with the source link. No figures from memory or the web in a note. Every written output is run through `python -m pmstack audit` before it is published.
- **Facts vs inference.** Label interpretation. No trade instructions. Size suggestions come only from `pmstack/sizing.py`, in paper risk units, as advice; decisions stay with the PM.
- **Log every agent run** with `python -m pmstack log --step <name> --fields '<json>'`.
- **Licences.** `pmstack/adapters/yahoo.py` is unofficial and personal-use only; do not port it. Never add Bloomberg-derived data to this repo.
- **Literature first.** Before building any agent, review the most cited papers, the Atlas investor cards and the specialist books; write `docs/research/<agent>.md` (finding → what it changes → source) and build from it.
- **Quant standards.** Alerts are not signals. Anything promoted to a signal goes through the quant-research gate (alpha vs beta, out-of-sample, multiple-testing haircut, costs, look-ahead and memorisation checks).

## Layout
- `config/sources.yaml` — data sources; one block per adapter (swap adapters here)
- `config/monitor.yaml` — alert thresholds
- `pmstack/` — adapters, store (Parquet + DuckDB), monitor, run log, CLI
- `data/obs/<source>/<year>.parquet`, `data/text/<source>.parquet` — research memory (numbers, policy text)
- `briefs/<date>/` — `facts.md`, `facts.json`, `alerts.json`, `note.md`
- `notes/` — research, calls, podcasts (markdown with YAML header); `notes/context.md` — standing facts Bernardo has stated (agents take them as given)
- `journal/<YYYY>/<id>.md` — decision journal (paper/example ideas only): conviction, payoff, invalidation, source, events, outcome; `pmstack/journal.py` runs the hard checks and stats
- `pmstack/sizing.py` — sizing assistant (agent 4): Kelly-relative units, cap, steps, drawdown cut (on the marked book since agent 8: open marks count), flags, review
- `pmstack/critic.py` + `config/critic.yaml` — critic (agent 5): card (outside view, reference class, tape, crowd, policy, alerts, Zweig triggers), slot plan, save/answer/withdraw/outcome, Friday `weekly`, `stats`. Code picks the questions; the model only words them; saved questions are frozen
- `pmstack/review.py` + `config/review.yaml` — weekly review (agent 6): process scorecard (process first, leaks, outcomes gated by sample size with intervals and shrinkage), goal catalogue and tracking (`journal/goals.yaml`), monthly section. Review week = 7 days ending 18:00 BRT Friday
- `pmstack/consensus.py` + `config/monitor.yaml` (`consensus:`) — consensus and narrative monitor (agent 7): GDELT attention stages for the frozen narratives (+1 validation query; copper, OPEC+, crop weather and gold retired 20 Oct 2026; oil glut and US fiscal folded into the news-feed Oil and product supply and Fiscal stress 21 Oct), trend-follower proxy (1/3/12-month vote, strength, flip levels), CFTC percentile beside it, labels and idea placement (all inference), Fed wording counts; `narrative_spreading` alert vs the previous pack. Descriptive only, every narrative "unvalidated" until GPR/EPU + headline audit
- `pmstack/risk.py` + `config/risk.yaml` — risk and crowding (agent 8): risk model (EWMA vol; calm and stress correlation, Ledoit–Wolf), risk table in R, effective independent ideas, clusters, stress P&L in R (replays, named driver shocks, worst case at k = 3; stops honoured and gapped), CTA levels, crowding per idea (red only when funding stresses), one marked book curve for amber and red warnings. Since v2 (10 Oct evening) stress runs on history back to 1986 (`risk.history`: futures from ~2000, spot/index/yield proxies before, roll screen): a 34-episode library (copper tariff pair added 24 Oct) replayed day by day, the worst 1/5/20/60-day windows for today's book, named shocks under stress/2008/2022 correlations. `risk.marked_drawdown` is also the sizing assistant's drawdown cut (open marks count). Only realised signals alert; nothing after the as-of date is used
- `pmstack/fetch.py` — `history_start` (prices, FRED: 1986) = one-time deep fetch per series, marked in `data/obs/<source>/_history.json`; a `--backfill` goes back to it too
- `pmstack/adapters/gdelt.py` — GDELT DOC 2.0 (free, keyless; cite "The GDELT Project" with a link). Unreachable from the cloud sandbox: runs in GitHub Actions only, with a 3-minute budget since 20 Oct (was 12; BigQuery measures every narrative) and 30–60 s backoff on HTTP 429; missing series are fetched first and catch up next run. Queries are frozen: an edit gets a new `_vN` id
- `pmstack/discovery.py` + `pmstack/adapters/gdelt_disc.py` + `config/discovery.yaml` (+ `config/sources.d/discovery.yaml`) — narrative discovery (agent 7, step 1 of 2; 20 Oct 2026): English GKG page-title words and word pairs counted once per source domain in BigQuery (~0.35 GB a day, shared byte ledger), day aggregates in `data/narratives/discovery/days/` (gitignored: kept in the data job's Actions cache, rebuilt by the backfill if evicted), each day scored vs its own trailing history (EWMA share z with a noise floor; day-1 "new" flag), candidates written once per day to `data/narratives/discovery/candidates/` and usable from the next day; "Narrative discovery" section in facts.md with point-in-time price and CFTC co-movement context. Step 2 is Bernardo's selection: `.claude/skills/narratives/` + `/narratives review` (promote / watch / dismiss, `decisions.jsonl`); promotion = draft query, `narratives measure`, headline audit (>= 70% precision), then a frozen definition in the Consensus map
- `docs/project/` — project hand-off docs (plan and status `agents-plan.md`, kickoff briefs, session notes `notes-A<n>.md`). Source of truth since 15 Oct 2026; start any new build session from `docs/project/agent-build-kickoff.md`
- `pmstack/adapters/gdelt_bq.py` — GDELT GKG via BigQuery (secrets `GCP_SA_KEY` JSON + `GCP_PROJECT_ID`, read from env only; Actions only): the same frozen queries matched on each article's title or URL path → `gdeltbqt:<qid>:count|share|tone`, `gdeltbqt:norm` (`gdeltbq:*` = URL path only, 15 Oct, kept, not updated); top headline links (title, source, URL, date only) → `data/text/gdelt_headlines.parquet`. Block `gdelt_bq_v2` (series `gdeltbq2:*`, first in the order since 16 Oct) holds frozen v2 definitions per narrative (`narrative:` key; title words plus `theme:NAME` GKG themes), chosen by `python -m pmstack narratives measure` (manual workflow `narratives-measure.yml`; results in `docs/research/narrative-measure/`)

## Parallel sessions (decided 20 Oct 2026)
- **One checkout per session.** Two Claude sessions never work in the same folder: a branch switch, merge or rebase in one changes the files under the other (this happened on 19–20 Oct). The main checkout `C:\Users\user\code\pm-agent-stack` belongs to one session at a time; every other session works in its own git worktree:
  `git worktree add ../pm-agent-stack-<task> -b <task-branch> origin/main`
  (from the Desktop app, start the session with "use a worktree"). Remove it when merged: `git worktree remove ../pm-agent-stack-<task>`.
- **Python:** a worktree has no `.venv`; use the main checkout's: `..\pm-agent-stack\.venv\Scripts\python -m pytest -q` (run from the worktree folder so `pmstack` is imported from it).
- **Merging:** `git pull --rebase origin main` and the full test suite in the worktree, then fast-forward `main` (`git push origin <task-branch>:main`). `logs/runs.jsonl` conflicts are resolved as the union of both sides ordered by `ts`.
- File ownership between tracks (see `docs/project/notes-and-keys-kickoff.md`) still applies inside worktrees.
